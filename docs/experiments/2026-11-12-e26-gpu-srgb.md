# 실험 E26: GPU 길에서 `window-colorspace = srgb`(Display P3 표시와 마지막 변환 패스)

- 날짜: 2026-11-12(주 세션이 잼)
- 관련 이슈: [#466](https://github.com/dj258255/b-terminal/issues/466), ADR-009(화면 색 공간), ADR-047
- 원자료: 주 세션 scratchpad의 `e26/` 폴더(측정 스크립트, 화면, 로그). 저장소에는 넣지 않는다
- 실험 빌드: e3ecf38(환경 변수 `BT_E26_SRGB`). 정식 동작(스위치 없음)은 523f4d7에서 바꾸고 실제 창에서 다시 쟀다: `srgb` GPU 길과 CPU `srgb`의 16색 차이 1, `display-p3`는 0.49.0 GPU 기본과 차이 0

## 찾은 경위

0.49 ROADMAP에서 `window-colorspace` 기본을 그대로 두기로 하면서, `srgb`면 GPU 길을 쓰지 못하는 것(`render_path::cpu_only_reason`)이 걸렸다. Ghostty 기본은 `srgb`이고 GPU로 색을 맞춘다. wgpu 30 소스에서 `SurfaceColorSpace::Srgb`는 레이어 색 공간을 nil로 두고 주석은 "레이어 기본은 sRGB로 다룬다"였다. 그 말대로면 지금 GPU 길이 이미 색을 맞추는 셈이라 먼저 쟀다.

## 조건

- Apple M2 Pro 내장 120Hz(Color LCD), macOS 26, release, 창 2000×1360px, 격리 `HOME`·`TMPDIR`, 저전력 모드 켜짐, 회마다 새로 띄움
- 색: `screencapture -l`로 창을 찍어 픽셀을 읽는다. 16색 장면은 `48;5;0`~`15` 바탕 칸 8칸씩을 한 줄로 찍고, 40px 넘게 이어지는 색 구간을 왼쪽부터 견준다(글자 가장자리는 길마다 래스터가 달라 뺀다)
- footprint는 `vmmap -summary`의 physical footprint

## 결과

### 1. 지금 길의 색(0.49.0, 바탕 #282c34)

| 길 | 픽셀 |
|---|---|
| GPU 기본(레이어 색 공간 nil) | (40,44,52) |
| CPU `display-p3` | (40,44,52) |
| CPU `srgb` | (41,44,51) |

- 레이어 색 공간이 nil이면 색을 맞추지 않는다(wgpu 주석과 다름, ADR-009의 설명이 맞음).
- 16색에서 CPU `srgb`와 GPU 기본의 차이는 채널당 최대 23이었다(ANSI 빨강 (197,87,87) 대 (213,78,83)).
- wgpu-hal metal은 Bgra8 형식에 `SRGB`(nil)·`DISPLAY_P3`만 알린다. 확장 sRGB는 `Rgba16Float`(EDR, 그림판 두 배)에서만 알려 택하지 않았다.

### 2. 실험 길: surface `DisplayP3` + 중간 텍스처 + 마지막 sRGB → Display P3 패스

변환은 sRGB 전달 함수를 풀고, 선형 sRGB(D65) → 선형 Display P3(D65) 행렬(CSS Color 4의 `lin_sRGB_to_lin_P3`와 소수 6자리까지 같음)을 곱한 뒤 다시 감는다. 섞기는 모두 중간 텍스처(sRGB 값)에서 일어나 CPU `srgb`와 같은 순서다. 사용자 셰이더 출력도 이 텍스처로 간다.

| 장면 | CPU `srgb`와 채널당 최대 차이 |
|---|---|
| 16색 바탕 칸 | 1 |
| 같은 장면 + 사용자 셰이더(가장자리 테두리만 그리고 안은 통과) | 1 |
| CPU `srgb` 두 회끼리 | 0 |

투명 창(`background-opacity = 0.8`)은 화면을 열어 깨짐이 없는 것만 보았다(색 칸은 불투명이라 값이 같음).

### 3. 비용(같은 실험 바이너리, GPU 기본 `display-p3`와 실험 길을 번갈아 다섯 회씩)

| | GPU 기본 | 실험 길 |
|---|---|---|
| `seq 1 300000` | 0.54~0.57초 | 0.55~0.58초 |
| 올린 프레임의 올리기까지(CPU 쪽) 중앙값 | 0.52~0.61ms | 0.53~0.60ms |
| 인코딩 중앙값 | 0.07ms | 0.08~0.10ms |
| 짧은 명령 뒤 footprint | 120.1~132.7MB(중앙 130.3) | 134.6~146.2MB(중앙 143.9) |
| `seq` 뒤 footprint | 161.4~166.3MB(중앙 163.5) | 174.8~178.3MB(중앙 177.2) |

- footprint는 약 13.6MB 늘었다. 중간 텍스처 한 장(10.9MB)과 그 밖의 것(가르지 않음)이다.
- GPU에서 변환 패스가 도는 시간은 로그에 없어 재지 않았다.
- 이 표의 footprint는 0.49.0의 제목 글꼴 메모리(#467)를 포함한다. 두 열이 같은 바이너리라 차이에는 영향이 없다.

## 판정

- `srgb`에서 GPU 길을 쓴다(넣음, ADR-047). CPU 길의 `srgb`는 큰 창에서 프레임마다 약 10~15ms가 들었다(E3).
- 기본은 `display-p3`로 둔다. 창마다 약 13.6MB를 기본으로 치를 만큼의 이득(채널당 많게는 23의 색 차이)은 아니라고 보았다. Ghostty와 다른 점으로 남긴다.

## 재지 않은 것

- 외부 화면(특히 sRGB 화면)에서의 색. 레이어에 Display P3 표시가 붙어 합성기가 화면에 맞추므로 맞을 것으로 보지만 외부 화면이 없다.
- 변환 패스의 GPU 시간, 60Hz·외부 화면, 저전력 모드를 끈 상태
- 중간 텍스처 없이 각 파이프라인 출력에서 바꾸는 길(섞기가 P3 값에서 일어나 글자 가장자리가 어긋나고 사용자 셰이더 출력을 바꿀 수 없어 택하지 않음)
- 투명 창 바탕의 색 값(곱한 알파를 나눠 바꾸고 다시 곱해 알파가 작을수록 8비트 양자화 오차가 큼)
