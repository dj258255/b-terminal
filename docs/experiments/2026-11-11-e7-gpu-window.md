# 실험 E7: GPU 창 길(`BT_GPU=1`)은 CPU 길보다 프레임이 빨리 올라가는가

- 날짜: 2026-11-11(만든 날). 잰 날은 주 세션이 적는다
- 관련 이슈: [#352](https://github.com/dj258255/b-terminal/issues/352), [실험 E5](2026-11-10-e5-iosurface.md), [실험 E6](2026-11-10-e6-wgpu-cells.md), [ADR-036](../decisions.md)
- 커밋: feature/gpu-window 브랜치(이 실험을 넣은 PR)
- 원자료: 주 세션 scratchpad의 `e7/` 폴더(회마다 로그). 저장소에는 넣지 않는다

## 가설

> 큰 창(2000×1360px 이상)에서 GPU 길은 격자 그리기와 올리기를 GPU가 맡으므로, 바뀐 줄 1줄 프레임의 "올리기까지"가 CPU 길(IOSurface, E5의 중앙값 1.37ms)보다 짧거나 같고, 통째 프레임(덧그림이 켜져 있어 층을 올리는 경우)은 CPU 길(E6: 통째 그리기 약 7ms)보다 짧다. 단 GPU 길의 "올리기까지"는 GPU가 끝나길 기다리지 않으므로 CPU 길의 같은 이름 값과 뜻이 다르다.

## 이 실험이 정할 것

> 두 시나리오(바뀐 줄 1줄, 통째)에서 다섯 쌍 모두 GPU 길의 중앙값이 CPU 길보다 짧으면 ADR-036의 "다음 판에 기본을 GPU로 바꿀 조건" 가운데 (1)을 채운 것으로 본다. 하나라도 길면 그 시나리오의 원인(층 올리기, `present` 대기)을 나눠 재는 실험을 따로 연다. 결과는 그대로 남긴다. 이 실험은 기본을 바꾸지 않는다.

## 조건

E3·E4·E5와 같게 한다.

- 기기: Apple Silicon Mac(arm64), macOS, `--release`, 내장 화면, 창 1000×680pt(2000×1360px), `window-colorspace` 기본
- 격리: 사용자 설정을 건드리지 않게 `HOME`을 빈 폴더로, `TMPDIR`을 짧은 경로로 바꾼다(제어 소켓 경로 길이 때문)
- 바꾼 변수: 그리기 길 하나(CPU = 환경 변수 없음 / GPU = `BT_GPU=1`). 두 조건을 **번갈아 다섯 번씩** 띄운다
- 시나리오 A(바뀐 줄 1줄): 화면을 채운 뒤 맨 윗줄만 0.2초마다 바꾼다. 덧그림이 없으므로 GPU 길은 층을 올리지 않고 격자만 다시 그린다
- 시나리오 B(통째): 단일 탭에서 진행 막대(OSC 9;4)가 켜져 있으면 덧그림이 켜져 매 프레임이 통째다(CPU 길도 통째로 그린다). 같은 줄 갱신에 진행 막대만 더한다
- 같은 설정 파일: 아무 설정도 주지 않는다(`background-opacity` 1, 배경 그림 없음, `window-colorspace` 기본). 그래야 GPU 길이 CPU로 돌아가지 않는다. 돌아갔으면 로그에 `BT_GPU=1이지만 CPU 길로 그린다`가 한 줄 나온다. 그 회는 버린다

## 지표 정의

E5와 같다. 앱이 `RUST_LOG=debug`일 때 프레임마다 찍는 한 줄에서 읽는다.

```
다시 그리기: 바뀐 줄 1줄 그리기 …ms, 올리기까지 …ms (크기 … 버퍼 … 옮기기 … present …)       ← CPU 길
다시 그리기: 통째 N줄 그리기 …ms, 올리기까지 …ms (GPU: 층 올리기 … 준비 … 제출·올리기 …, Presented)  ← GPU 길
```

- 그리기: CPU가 층을 그린 시간(통째가 아닌 프레임은 0에 가깝다).
- 올리기까지: GPU 길은 프레임 시작부터 `present`를 부탁한 때까지, CPU 길은 올리기 시작부터 끝까지다. **GPU 길은 GPU가 끝나길 기다리지 않으므로 이 값만으로 화면에 보일 때까지의 시간을 말할 수 없다.** 이 실험은 그 한계를 안고 같은 이름의 값을 견준다. GPU 완료까지는 Metal System Trace 같은 도구가 필요하고 이번에 재지 않는다.
- GPU 길의 내역: `층 올리기`(아래·위층 텍스처 올리기), `준비`(인스턴스 만들기와 새 글리프), `제출·올리기`(그리기 명령 제출과 `present` 부탁). 통째가 아닌 프레임은 `층 올리기`가 0이다.
- 프레임마다의 중앙값을 한 회의 값으로 쓰고, 다섯 회의 중앙값을 비교한다.

## 잴 명령

주 세션이 창을 띄워 잰다. 이 문서를 쓴 에이전트는 창을 띄우지 않았다.

1. 빌드: `cargo build --release -p bt-app`
2. CPU 길: `RUST_LOG=debug HOME=<빈 폴더> TMPDIR=/tmp/bt ./target/release/b-terminal 2> e7-cpu-<시나리오>-<회>.log`
3. GPU 길: 위와 같고 환경 변수만 더한다: `BT_GPU=1 RUST_LOG=debug …` (로그 이름은 `e7-gpu-…`)
4. 창 크기를 1000×680pt(2000×1360px)로 맞춘다.
5. 시나리오 A: 창 안의 셸에서(주 세션은 `btctl send`로 보낸다) E5와 같은 명령.
   ```
   clear; seq 1 80
   i=0; while [ $i -lt 60 ]; do printf '\033[1;1H%05d' $i; sleep 0.2; i=$((i+1)); done
   ```
6. 시나리오 B: 위와 같고 진행 막대를 켠다.
   ```
   printf '\033]9;4;1;50\033\\'
   clear; seq 1 80
   i=0; while [ $i -lt 60 ]; do printf '\033[1;1H%05d' $i; sleep 0.2; i=$((i+1)); done
   printf '\033]9;4;0;0\033\\'
   ```
7. 중앙값: 로그에서 해당 프레임의 "올리기까지"만 뽑아 가운데 값을 낸다(A는 `바뀐 줄 1줄`, B는 `통째`).
   ```
   grep '바뀐 줄 1줄' e7-<길>-A-<회>.log | sed -E 's/.*올리기까지 ([0-9.]+)ms.*/\1/' | sort -n | awk '{a[NR]=$1} END {print a[int((NR+1)/2)]}'
   grep '통째' e7-<길>-B-<회>.log | sed -E 's/.*올리기까지 ([0-9.]+)ms.*/\1/' | sort -n | awk '{a[NR]=$1} END {print a[int((NR+1)/2)]}'
   ```
8. 두 길을 시나리오마다 번갈아 5회씩 하고 쌍마다 표에 옮긴다.

## 실제 창에서 볼 것(화면)

재기와 별개로 GPU 길이 CPU 길과 같게 보여야 하는 것들이다. 같은 설정으로 `BT_GPU=1`과 기본의 화면을 나란히 본다(화면 그림을 찍어 픽셀로 견주면 좋다).

- 분할 두 칸: 칸마다 자리에 그려지는지, 글자가 옆 칸을 덮지 않는지
- 고르지 않은 칸 흐림(`unfocused-split-opacity`)이 칸 전체에 고르게 들어가는지
- 탭 둘: 탭 막대와 활성 탭 표시
- Cmd-Shift-P 팔레트와 그 아래 격자가 비쳐 보이지 않는지
- 확인 막대(예: 프로그램이 도는 칸을 닫으려 할 때)
- kitty 그림 한 줄(`printf`로 띄운다): 격자 글자 위에 얹히는지
- 색: 기본 색 공간에서 바탕·글자색이 CPU 길과 같은지(ADR-036 결정 7이 확인하지 못한 부분)
- 창 크기를 끌어 바꿀 때 깜빡임·옛 크기 그림이 남지 않는지, Retina에서 흐리지 않은지
- 투명 창·배경 그림·`window-colorspace = srgb`를 주면 로그에 CPU로 돌아갔다는 한 줄이 나오고 CPU 길과 같게 보이는지

## 창 없이 확인한 것(에이전트, 한 번 잰 값)

- 창 없이 합친 프레임(아래층 + 자리가 다른 두 칸 + 반투명 포함 위층, 258024픽셀)은 CPU 캔버스에 같은 순서로 그린 프레임과 391픽셀이 달랐고 채널 최대 차이는 1이었다(차이가 1을 넘는 픽셀 0개). Apple M2 Pro(Metal) 한 대에서 한 번 잰 값이다.
- 창 surface(`present`)와 앱 연결은 창 없이 시험할 수 없어 시험하지 않았다.
