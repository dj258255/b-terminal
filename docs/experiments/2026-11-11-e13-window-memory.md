# 실험 E13: GPU 길 창 하나의 메모리(빈 위층, 층 올리기 임시 버퍼)

- 날짜: 2026-11-11(주 세션이 잼)
- 관련 이슈: [#386](https://github.com/dj258255/b-terminal/issues/386)(추적), [#387](https://github.com/dj258255/b-terminal/issues/387), [#388](https://github.com/dj258255/b-terminal/issues/388), [실험 E12](2026-11-11-e12-gpu-step5.md)
- 원자료: 주 세션 scratchpad의 `e13/` 폴더(`vmmap -summary` 출력, 화면 찍은 것). 저장소에는 넣지 않는다

## 조건(공통)

- 기기: Apple M2 Pro, macOS 26, 내장 화면(120Hz), `--release`, 창 1000×680pt(2000×1360px), GPU 길(기본)
- 격리: `HOME`을 빈 폴더로, `TMPDIR`을 짧은 경로로. 설정은 `window-save-state = never`, `shell-integration = none`
- 재는 값: `vmmap -summary`의 Physical footprint. RSS(`ps -o rss=`)에는 GPU 텍스처(owned unmapped graphics)가 빠져서, E12 A절의 RSS 대신 이것을 쓴다
- 장면: 앱을 띄워 화면 가득 출력(60줄)을 그리고 2초 뒤 잰다. `btctl new --window`로 창을 더해 같은 출력을 그리고 다시 잰다
- 견줄 두 빌드를 번갈아 회마다 새로 띄운다

## 먼저 잰 것: 창 하나를 더하면 무엇이 느는가

origin/main(0.34.0, 3b50809)에서 창 1개 → 2개(한 번씩).

| | footprint | 늘어난 주요 영역 |
|---|---|---|
| GPU 길 | 155.3 → 273.3MB(+118) | MALLOC_LARGE +52.0, IOSurface +31.6, owned unmapped graphics +29.9, MALLOC_SMALL +4.8 |
| CPU 길(`BT_GPU=0`) | 80.2 → 126.2MB(+46) | IOSurface +31.4, MALLOC_LARGE +10.4 |

- 창 크기 버퍼 한 장은 2000×1360×4 = 10.9MB다. GPU 길의 MALLOC_LARGE +52MB는 약 다섯 장이다. 코드로 보면 아래층 프레임, 위층, 아래층 사본, 위층 사본, 올리기 임시 버퍼다.
- IOSurface(약 31MB)는 창의 그림판으로, 두 길이 같다.
- owned unmapped graphics(약 30MB)는 GPU 텍스처(아래층, 위층, 합친 그림 등)다.

## A. 위층에 그린 것이 없으면 위층을 놓는다(#387)

### 가설

> 위층(kitty 그림, 흐린 칸, 팔레트, 확인 막대 등)은 대개 비어 있다. 그래도 앱은 창 크기 버퍼를, 렌더러는 사본과 텍스처를 늘 쥔다. 비었을 때 셋을 놓으면 창 하나에 약 33MB(10.9MB × 3)가 준다.

### 방법

- 고친 것
  - 앱이 위층을 다 그린 뒤 0이 아닌 픽셀이 없으면 버퍼를 놓고, 렌더러에 빈 조각을 넘긴다.
  - 렌더러는 빈 조각을 받으면 위층 텍스처와 사본을 놓는다.
  - 다음 프레임에 그릴 것이 생기면 둘 다 새로 잡는다.
- 견준 빌드: 기준은 origin/main(3b50809), 새 빌드는 #387 브랜치. 번갈아 세 쌍.

### 결과(세 쌍, footprint)

| | 창 1 | 창 2 |
|---|---|---|
| 기준 | 154.9~155.3MB | 273.0~273.3MB |
| #387 | 122.8~123.0MB | 208.9~209.8MB |
| 차이 | 약 −32MB | 약 −64MB |

창 하나일 때 줄어든 영역(둘째 쌍):

| 영역 | 기준 | #387 | 차이 |
|---|---|---|---|
| MALLOC_LARGE | 57.4MB | 36.6MB | −20.8(위층 버퍼와 사본) |
| owned unmapped graphics | 29.8MB | 18.7MB | −11.1(위층 텍스처) |
| footprint | 154.9MB | 122.8MB | −32.1 |

- 줄어든 양이 가설의 세 장과 맞는다. 창이 둘이면 두 배가 준다.
- RSS도 창 1개 174.8MB → 153.3MB, 창 2개 232.9MB → 190.1~190.9MB로 줄었다(텍스처 몫은 RSS에 없다).

### 화면이 같은가

같은 장면을 두 빌드에서 차례로 찍어 픽셀을 견주었다(커서 깜빡임을 끈 설정, 한 회씩).

| 장면 | 기준 대 #387 |
|---|---|
| 1. 한 칸에 30줄 출력 | 다른 픽셀 0/2,720,000 |
| 2. `btctl new --split right`로 나눠 같은 출력(고르지 않은 왼쪽 칸이 위층에서 흐려짐) | 다른 픽셀 0 |
| 3. 나눈 칸에서 `exit`(위층이 다시 빔) | 다른 픽셀 0 |

- #387의 장면 3은 장면 1과 픽셀까지 같았다. 놓았던 위층이 장면 2에서 돌아오고, 장면 3에서 흐림이 남지 않았다.

### 판정

넣는다.

## 한계

- 한 기기(Apple M2 Pro 내장 화면)의 값이다.
- 위층이 빈 프레임에서 통째로 그릴 때마다(창 크기를 바꾸는 중 등) 버퍼를 새로 잡고 0이 아닌 픽셀을 찾는다. 그 시간은 재지 않았다.
- 팔레트, kitty 그림, 확인 막대가 떴다 사라지는 장면은 찍어 견주지 않았다. 창 없는 시험(`empty_upper_slice_releases_the_upper_layer_and_it_comes_back`)으로 위층이 놓였다가 돌아오는 것만 보았다.
