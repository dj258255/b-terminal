# 실험 E18: 입력 → 올리기 지연

- 날짜: 2026-11-11(주 세션이 잼)
- 관련 이슈: [#415](https://github.com/dj258255/b-terminal/issues/415)(추적), [#417](https://github.com/dj258255/b-terminal/issues/417)
- 원자료: 주 세션 scratchpad의 `e18/lat/` 폴더(측정 스크립트, 로그). 저장소에는 넣지 않는다

## 가설

> 0.32부터 판마다 "키 입력 지연은 재지 않았다"로 적었다. #417의 debug 로그(`입력 → 화면:`)로 PTY에 쓴 때부터 그 결과가 든 프레임을 올릴 때까지를 잴 수 있다. 앱이 쉬고 있을 때 한 글자의 메아리는 프레임 미룸(ADR-038)에 걸리지 않고 바로 올라가, 화면 갱신 한 주기(120Hz에서 8.3ms)보다 짧을 것이다.

## 조건

- 기기: Apple M2 Pro, macOS 26, 내장 화면(120Hz), `--release`, 창 2000×1360px
- 빌드: #417 브랜치(0.39.0 + 지연 로그), `RUST_LOG=b_terminal=debug`
- 격리: `HOME`을 빈 폴더로, `TMPDIR`을 짧은 경로로. 설정은 `window-save-state = never`, `shell-integration = none`, `cursor-style-blink = false`
- 1분 부하 6~16(다른 서브에이전트가 빌드하고 있었다)

## 방법

1. 앱을 띄우고 칸에서 `exec /bin/cat`을 돌린다. 그러면 메아리는 터미널 드라이버가 만든다.
2. `btctl send x`(Enter 없음)를 0.2초 간격으로 40번 보낸다.
3. 로그의 `입력 → 화면:` 줄을 모은다.
4. 이를 GPU 길 `window-vsync = true`(기본)·`false`, CPU 길(`BT_GPU=0`)에서 앱을 새로 띄워 세 회씩 잰다.
5. zsh 프롬프트(줄 편집기가 메아리를 만듦)에서도 한 회 잰다.

`btctl send`는 키 이벤트가 아니다. 그래서 이 값에는 OS가 키를 앱에 넘기기까지의 시간과 키 인코딩이 들지 않는다. 또 `present`가 돌아온 때까지이므로, 화면 합성과 패널에 보이기까지의 시간(최대 화면 갱신 한 주기 남짓)도 들지 않는다.

## 결과

| 길 | 줄 수 | 입력 → 올리기 중앙값 | p90 | 최대 | 출력 받음까지 중앙값 | 그리기 시작까지 중앙값 |
|---|---|---|---|---|---|---|
| GPU, `window-vsync = true` | 123 | 0.9ms | 1.5ms | 4.0ms | 0.0ms | 0.1ms |
| GPU, `window-vsync = false` | 123 | 0.8ms | 1.3ms | 2.0ms | 0.0ms | 0.1ms |
| CPU(`BT_GPU=0`) | 123 | 1.8ms | 3.0ms | 4.0ms | 0.0ms | 0.1ms |
| GPU, zsh 프롬프트 | 40 | 1.0ms | 1.6ms | 1.9ms | 0.1ms | 0.2ms |

- 줄 수는 보낸 글자마다 하나에 `exec /bin/cat` 줄이 하나씩 더해진 것이다. 메아리마다 한 줄씩 찍혔다.
- 메아리(`출력 받음까지`)와 화면 뜨기(`그리기 시작까지`)는 0.2ms 안이다. 남은 시간은 그리기와 올리기다.
- 앱이 쉬고 있을 때 한 글자는 다음 화면 갱신을 기다리지 않고 1ms 안팎에 올라갔다. `window-vsync`는 이 경우 차이가 작았다(중앙값 0.1ms).
- CPU 길은 GPU 길의 약 두 배였다(그림판을 CPU로 채워 올림).

## 판정

- 가설이 맞았다. 앱 몫(PTY 쓰기 → 올리기)은 쉬는 창에서 GPU 길 1ms 안팎이다.
- 사람이 느끼는 키 → 화면 지연은 이 값보다 OS 키 전달과 화면 합성·패널 쪽이 클 것으로 보이지만, 그것은 이 기계에서 재지 못했다.
- 빠른 출력 중의 입력(프레임 미룸이 켜진 동안)은 재지 않았다. 다음에 볼 곳이다.

## 재지 않은 것

- OS 키 이벤트 → 앱, `present` → 패널 표시
- 빠른 출력이나 큰 화면 변경 중의 입력, 60Hz 외부 화면, 칸 여러 개
