- 날짜: 2026-11-11(주 세션이 잼)
- 관련 이슈: [#392](https://github.com/dj258255/b-terminal/issues/392)(추적), [#393](https://github.com/dj258255/b-terminal/issues/393), [#394](https://github.com/dj258255/b-terminal/issues/394), [실험 E13](2026-11-11-e13-window-memory.md)
- 원자료: 주 세션 scratchpad의 `e13/`, `e14/` 폴더(`vmmap -summary` 출력, debug 로그, 화면 찍은 것). 저장소에는 넣지 않는다
- 구현은 서브에이전트가 각자 worktree에서 했고, 실제 창 측정은 주 세션이 했다

## 조건(공통)

- 기기: Apple M2 Pro, macOS 26, 내장 화면(120Hz), `--release`, 창 1000×680pt(2000×1360px), GPU 길(기본)
- 격리: `HOME`을 빈 폴더로, `TMPDIR`을 짧은 경로로. 설정은 `window-save-state = never`, `shell-integration = none`, `cursor-style-blink = false`
- 메모리: `vmmap -summary`의 Physical footprint. 앱을 띄워 60줄을 그린 뒤 창 1개, `btctl new --window`로 창 2개
- 회마다 앱을 새로 띄우고, 견줄 두 쪽을 번갈아 돌린다
- 기준 빌드: origin/main 7ccab99(0.35.0)

## A. 그림판 3장 → 2장(#394)

### 가설

> wgpu Metal은 `desired_maximum_frame_latency + 1`장의 그림판을 쓴다(wgpu-hal 30 `metal/surface.rs` 330줄). 지연을 2에서 1로 낮추면 창마다 그림판 한 장(약 10.5MB)이 준다. 그림판을 기다리는 시간(얻기)은 늘 수 있다.

### 방법

- 측정용 환경 변수 `BT_FRAME_LATENCY`(1~3)를 더한 빌드 하나로 1과 2를 번갈아 띄운다.
- 잰 것
  - footprint(세 쌍)
  - 빠른 출력: `seq 1 300000`, `seq 1 3000000`. 부하 7~9에서 한 번(세 쌍·두 쌍), 부하 3~5에서 다시(다섯 쌍·두 쌍)
    - `btctl send` 뒤 `btctl wait`로 끝날 때까지의 시간을 잰다.
    - debug 로그에서 올린 프레임 수와 그 `얻기` 합을 모은다(띄운 때부터 끌 때까지 전체).
  - 탭 열고 닫기 열 번(세 쌍): 통째 프레임 수, 미룬 프레임 누적

### 결과

| | 지연 2(그림판 3장) | 지연 1(그림판 2장) |
|---|---|---|
| footprint 창 1 | 113.6~114.8MB | 102.1~113.5MB |
| footprint 창 2 | 190.3~193.9MB | 178.5~180.0MB |
| IOSurface 창 1 / 창 2 | 31.5 / 63.1MB | 21.0 / 52.6MB |
| `seq 1 300000` 걸린 시간(부하 3~5, 다섯 쌍) | 0.53~0.57초 | 0.54~0.58초 |
| 그 얻기 평균 | 0.44~0.90ms | 0.38~0.59ms |
| `seq 1 3000000` 걸린 시간(부하 3~5, 두 쌍) | 7.15~7.22초 | 7.24~7.27초 |
| 그 올린 프레임 / 얻기 합 | 431~435장 / 137~141ms | 427~438장 / 84~86ms |
| `seq 1 300000` 걸린 시간(부하 7~9, 세 쌍) | 0.55~0.58초 | 0.57~0.68초 |
| `seq 1 3000000` 걸린 시간(부하 7~9, 두 쌍) | 7.06~7.27초 | 7.34~7.37초 |
| 탭 열고 닫기 통째 프레임 / 미룬 프레임 | 37~39장 / 15~18 | 29장 / 23~28 |

- 그림판이 한 장 줄어 창마다 약 10.5MB가 줄었다.
  - 지연 1의 한 회(창 1)는 IOSurface가 31.5MB로 남았다(113.5MB). 까닭은 가리지 않았다.
- 얻기는 늘지 않고 오히려 줄었다.
- 출력 시간
  - 부하 7~9에서는 지연 1이 1~4% 더 걸렸다.
  - 부하 14~15에서 따로 돌린 세 쌍(`seq 1 300000`)은 0.67~0.88초 대 0.87~1.00초였다.
  - 부하 3~5에서 다시 재니 차이가 1% 안팎으로 흔들림 안이었다. 부하가 높을 때의 차이는 흔들림으로 본다.
- 탭 열고 닫기에서는 지연 1이 한 주기 안의 프레임을 더 미뤄 하나로 합쳤다. 그래서 통째 프레임이 적다(마지막 화면은 같다).
- 메모리와 탭 열고 닫기는 1분 부하 7~9에서 쟀다(다른 에이전트가 빌드 중).
- 기본값을 1로 바꾼 빌드를 환경 변수 없이 띄우면 로그에 `프레임 지연 1(그림판 2장)`이 찍힌다.

### 판정

기본값을 1로 바꾼다. `BT_FRAME_LATENCY=2`로 예전처럼 띄울 수 있다.

## 한계

- 한 기기(Apple M2 Pro 내장 120Hz 화면)의 값이다. 60Hz 외부 화면에서 지연 1의 얻기 시간은 재지 않았다.
- 키를 친 뒤 화면에 보이기까지의 지연(입력 지연)은 재지 않았다. 키 입력을 흉내 내지 않는다.
